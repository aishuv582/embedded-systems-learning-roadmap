🔌 Day 136: SPI Protocol
1. What is SPI?

SPI (Serial Peripheral Interface) is a synchronous serial communication protocol used for short-distance communication between a microcontroller and peripheral devices.

Common SPI devices include:

Sensors
Flash memory
ADC/DAC
Displays
SD cards
EEPROM

SPI is generally faster than I²C but requires more pins.

2. SPI Architecture

SPI typically uses a Master–Slave architecture.

             MCU / Master
          ┌───────────────┐
          │               │
          │     SPI       │
          └─┬──┬──┬──┬────┘
            │  │  │  │
           SCLK MOSI MISO CS
            │  │  │  │
          ┌─▼──▼──▼──▼────┐
          │ SPI Peripheral │
          │    / Slave     │
          └───────────────┘
3. Four SPI Signals
Signal	Meaning	Direction
SCLK	Serial Clock	Master → Slave
MOSI	Master Out Slave In	Master → Slave
MISO	Master In Slave Out	Slave → Master
CS/SS	Chip Select / Slave Select	Master → Slave
🔹 SCLK

Clock generated by the master.

🔹 MOSI

Carries data from Master → Slave.

🔹 MISO

Carries data from Slave → Master.

🔹 CS/SS

Selects which slave should communicate.

4. Why does SPI need CS?

Suppose one microcontroller communicates with three devices:

                 MCU
                  │
       ┌──────────┼──────────┐
       │          │          │
      CS1        CS2        CS3
       │          │          │
    Sensor      Flash      Display

The master activates the appropriate CS line.

For example:

CS1 = LOW → Sensor selected
CS2 = HIGH
CS3 = HIGH

Only the selected slave communicates.

5. SPI Data Transfer

SPI usually transfers data full-duplex.

At the same time:

Master → MOSI → Slave
Master ← MISO ← Slave

For example:

Master sends:  10110010
Slave sends:   01010101

Both can be transferred simultaneously.

6. SPI Clock Modes

SPI has four modes, determined by:

CPOL – Clock Polarity
CPHA – Clock Phase
Mode	CPOL	CPHA
Mode 0	0	0
Mode 1	0	1
Mode 2	1	0
Mode 3	1	1

The master and slave must use the same SPI mode.

7. SPI vs I²C
Feature	SPI	I²C
Wires	Usually 4+	2
Speed	Higher	Lower
Full duplex	Yes	No
Addressing	No	Yes
Multiple devices	CS lines required	Device addresses
Hardware complexity	Simple	More protocol overhead
Common use	Flash, displays, ADC	Sensors, EEPROM
